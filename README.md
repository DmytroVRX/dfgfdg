## 1. Планування та архітектура застосунку

### Схема компонентів (Component Hierarchy)

```
                     ┌────────────────────────┐
                     │       <App />          │
                     │  (Батьківський стан)   │
                     └───────────┬────────────┘
                                 │
             Передача даних через props (.map)
                                 │
         ┌───────────────────────┼───────────────────────┐
         ▼                       ▼                       ▼
┌──────────────────┐   ┌──────────────────┐   ┌──────────────────┐
│  <CourseCard />  │   │  <CourseCard />  │   │  <CourseCard />  │
│     (Курс 1)     │   │     (Курс 2)     │   │     (Курс 3)     │
└──────────────────┘   └──────────────────┘   └──────────────────┘
```

### Визначення даних, що передаються через `props`:

| Назва prop | Тип даних | Опис / Призначення | Обов'язковість |
| :--- | :--- | :--- | :--- |
| `title` | `string` | Назва навчального курсу | Так (вимога ТЗ) |
| `instructor` | `string` | ПІБ або ім'я викладача | Так (вимога ТЗ) |
| `duration` | `string` | Тривалість курсу (тижні, години) | Так (вимога ТЗ) |
| `isAvailable` | `boolean` | Доступність запису (`true` - відкрито, `false` - закрито) | Так (вимога ТЗ) |
| `availableSeats` | `number` | Кількість вільних місць | Додатково |
| `level` | `string` | Рівень складності (Початковий, Середній тощо) | Додатково |
| `category` | `string` | Категорія/напрямок курсу | Додатково |
| `icon` | `string` | Тематичний емодзі/іконка | Додатково |
| `isEnrolled` | `boolean` | Статус, чи записався користувач на цей курс | Індивідуальне завд. |
| `onEnroll` | `function` | Callback-функція для обробки натискання на кнопку | Індивідуальне завд. |

## 2. Відповіді на 3 обов'язкові запитання (Аналіз власного рішення)

### Питання 1: Чому ви створили один компонент `CourseCard`, а не три окремі компоненти?
> **Відповідь:**  
> Ми створили один компонент `CourseCard`, дотримуючись ключового принципу програмування **DRY (Don't Repeat Yourself)** та філософії компонентного підходу React. Всі три картки мають однакову структуру, логіку відображення та стилізацію, а відрізняються лише даними (контентом). Створення трьох окремих компонентів призвело б до дублювання коду, ускладнення підтримки та неможливості масштабування застосунку. Завдяки одному компоненту ми можемо змінити дизайн чи верстку в одному місці, і зміни автоматично застосуються до всіх карток.

### Питання 2: Як дані потрапляють із компонента `App` до `CourseCard`?
> **Відповідь:**  
> Дані передаються зверху вниз за односпрямованим потоком даних (**One-way data binding**) за допомогою механізму **props (властивостей)**.  
> У компоненті `App` оголошено масив об'єктів `courses`. Ми ітеруємо цей масив за допомогою методу `.map()` і повертаємо екземпляр `<CourseCard />`, вказуючи значення у вигляді атрибутів:  
> `<CourseCard title={course.title} instructor={course.instructor} duration={course.duration} isAvailable={course.isAvailable} />`.  
> Усередині `CourseCard` ці значення приймаються через аргумент функції (деструктуризація об'єкта `props`) і вставляються у відповідні місця JSX-розмітки.

### Питання 3: Що потрібно змінити, щоб додати четвертий навчальний курс?
> **Відповідь:**  
> Завдяки використанню методу `.map()` структуру компонентів або верстку змінювати **не потрібно взагалі**. Достатньо лише додати новий об'єкт із полями нового курсу до масиву даних `courses` у батьківському компоненті `App` (або у файлі `courses.js`):
> ```javascript
> {
>   id: 4,
>   title: "DevOps та хмарні сервери (Docker & CI/CD)",
>   instructor: "Василь Бондаренко",
>   duration: "7 тижнів (28 годин)",
>   isAvailable: true
> }
> ```
> React автоматично згенерує четверту картку. У нашому застосунку це можна наочно продемонструвати прямо в інтерфейсі, натиснувши кнопку **"+ Додати 4-й курс"**.

## 3. Індивідуальне завдання

У проекті вже реалізовано інтерактивний функціонал, який перевершує стандартні вимоги:
1. **Інтерактивний запис на курс:** Кнопка "Записатися на курс →", яка перевіряє prop `isAvailable`, блокується, якщо запис закрито, а при натисканні фіксує запис, змінює стан кнопки на "✓ Ви записані", оновлює лічильник у шапці та показує спливаюче сповіщення.
2. **Фільтрація курсів:** Перемикач "Всі курси" / "Тільки доступні".
3. **Живе тестування props:** Кнопка "⚡ Змінити props курсу №1", яка на льоту змінює статус доступності, щоб миттєво довести викладачеві реакцію інтерфейсу на зміну props.

### Якщо викладач дасть специфічну додаткову вимогу:
- **Вимога "Додати пошук за назвою":** Додати `<input value={search} onChange={e => setSearch(e.target.value)} />` та профільтрувати `courses.filter(c => c.title.toLowerCase().includes(search.toLowerCase()))`.
- **Вимога "Додати ціну або знижку":** Додати prop `price` у `CourseCard` та вивести `{price ? `${price} грн` : 'Безкоштовно'}`.
- **Вимога "Змінити колір картки залежно від тривалості":** Передати у `CourseCard` умовний клас `duration.includes('10') ? 'card--long' : ''`.

## 4. Звіт про використання штучного інтелекту (ШІ)

*Цей розділ обов'язковий відповідно до умов завдання.*

1. **Як саме використовувався ШІ:**
   - ШІ було використано як асистента для швидкого розгортання структури проекту на Vite + React.
   - Для генерації початкового масиву навчальних курсів українською мовою з реалістичними даними.
   - Для створення сучасної CSS-стилізації (темна тема, градієнти, адаптивна сітка, анімації).
   - Для формулювання чітких академічних відповідей на контрольні запитання захисту.

2. **Які рекомендації ШІ було прийнято:**
   - **Прийнято:** Деструктуризація `props` прямо в сигнатурі функції `CourseCard({ title, instructor, duration, isAvailable })` — це робить код набагато чистішим і наочнішим.
   - **Прийнято:** Винесення тестових даних в окремий файл `data/courses.js` для розділення логіки та даних.
   - **Прийнято:** Додавання панелі з живою зміною `props`, що дозволяє наочно продемонструвати викладачеві виконання критерію №3 без перезавантаження сторінки.

3. **Які рекомендації ШІ було відхилено і чому:**
   - **Відхилено:** Пропозицію використати TailwindCSS або зовнішні UI-бібліотеки (MUI / Ant Design).  
     *Причина відхилення:* Завдання навчальне, важливо показати розуміння чистого CSS, модульності та flexbox/grid без перевантаження проекту сторонніми залежностями.
   - **Відхилено:** Початкову пропозицію створити єдиний масив у `App.jsx` з жорстко закодованими 3 компонентами без методу `.map()`.  
     *Причина відхилення:* Використання `.map()` демонструє професійний підхід і робить відповідь на питання №3 про додавання 4-го курсу елементарною.

## 5. Інструкція для самостійного запуску та захисту

Оскільки запуск на локальному комп'ютері викладача або студента потребує виконання термінальних команд, ось покроковий алгоритм:

1. **Запуск проекту:**
   ```bash
   npm run dev
   ```
2. Відкрийте у браузері адресу: `http://localhost:5173`
3. **Хід демонстрації на захисті:**
   - Покажіть три картки курсів.
   - Зверніть увагу на відображення 4 обов'язкових полів у кожній картці (назва, викладач, тривалість, доступність).
   - Натисніть кнопку **"⚡ Змінити props курсу №1"** і покажіть, як статус першого курсу змінюється з "Запис відкрито" на "Місць немає" (доказ реактивності props).
   - Натисніть кнопку **"+ Додати 4-й курс"** і продемонструйте появу четвертого курсу.
   - Відкрийте файл `src/components/CourseCard.jsx` та поясніть деструктуризацію props.
